## Intentional implementation choices requiring traceability

- Approved images move to a separate **private delivery bucket**. The public image endpoint checks property, post and submission state on every request, sends `no-store`, and never issues a permanent download token. This implements public display while preserving takedown control; production IAM remains GC-04.
- Guest sessions use one named Firebase app per property. They do not reuse or sign out the host's account, and the server refuses to bind one anonymous UID to a second property. No guest name/email field or cross-device identity is introduced.
- The pending message distinguishes provider-unavailable screening from ordinary host review. Standard and critical classifications share the handbook's neutral host-review wording; internal escalation details are not returned to guests.
- Testing classifications are injected only into the trusted in-process test helper. There is no HTTP request field, guest action or host action that can select a fake screening result.
