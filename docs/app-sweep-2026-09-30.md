# DigiStayBook app sweep — 30 September 2026

## Scope and proof

Compared the current React, Firebase Functions, Firestore/Storage rules, public pages and local tests with `handbook/DIGISTAYBOOK_BUSINESS_AND_OPERATING_PLAN.html` (BOP). Existing gap documents were leads, not evidence of current behaviour. Reviewed the landing, demo, in-stay demo, Privacy & Safety and Terms pages in a local desktop browser. Did not sign into a real host account, access deployed Firebase/Stripe/email settings, or run a physical-phone journey. A source finding below does not establish that the same version is deployed.

`npm run check` passed: TypeScript, 554 unit/component tests, Vite build and Functions build. The build warned about two JavaScript chunks over 500 kB and an ineffective dynamic import. Root production `npm audit --omit=dev` found zero advisories. Functions production audit found eight transitive advisories (one high, seven moderate). `npm run test:server` stopped at the guest-contribution fixture described below; subsequent integration checks did not run.

Priority: **P0** = must resolve before taking paid public usage; **P1** = significant BOP, security, or core journey defect; **P2** = usability, completeness, or release evidence. A decision already recorded by the user is called out as a BOP-document mismatch, not an instruction to reverse that decision.

## Recommended order

1. Prevent paid-property Delete from stranding subscriptions; finish policy/consent publication; choose and connect screening, then correct landing claims.
2. Repair the server test fixture and run the full emulator suite; resolve media URL exposure, reporting abuse behaviour and retention/deletion.
3. Complete billing recovery, support, privacy operations and delivered email; verify in an isolated preview with Stripe test mode.
4. Finish pinned/display controls, QR/export journeys and host/guest UX; run phone, keyboard, contrast and poor-network checks.
